# PRD — Blazelink 網站架設站

> 依據 `design-brief.md`（兩輪訪談，2026-09-29 定案）。本文件只記錄已經拍板的事項，還沒決定的事項列在文末「開放問題」，不預設答案。

## 範圍

- **技術架構**：Next.js 前台＋headless WordPress（WPGraphQL），訂單使用 WooCommerce，金流與電子發票串接綠界。
- **設計基準**：desktop 1920px，需要做響應式。全站只做繁體中文。
- **頁面清單**：首頁、網站案例、專欄列表頁、專欄文章內頁、商城頁、商品頁、購物車、結帳、付款成功頁、付款失敗頁、聯繫我們、諮詢送出後的感謝頁。
- **全站導覽**：右側固定的直立窄欄，由上到下依序是：網站案例／關於我們／專欄／商城／聯繫我們。

## MoSCoW 功能清單

### Must Have

**M-01 全站側邊欄導覽**
- 桌機：右側固定窄欄（約 80～120px），導覽文字直排，捲動時一直留在畫面上。導覽依照上方順序排列，欄內底部放購物車（顯示商品數量）和諮詢按鈕。
- 手機：側邊欄收成右上角的漢堡按鈕，按下後展開全螢幕選單，購物車和諮詢按鈕也在選單裡。
- 驗收：在 1280px、1440px、1920px 的寬度下，側邊欄都不會遮住內容；手機選單可以用鍵盤和螢幕閱讀器操作。

**M-02 Hero**
- 版面：logo 在左上角，中間是 9:16 影片（不滿版），底部是光影，右下是 News 輪播。
- 影片：業主用 Jitter 製作，長度約 13 秒，靜音自動循環播放，沒有聲音按鈕。提供 WebM 和 MP4 兩種格式，桌機版約 3MB 以內，手機版約 1～1.5MB。影片載入前先顯示封面圖，封面圖就是 LCP 元素。
- 桌機光影：用 WebGL shader 製作。滑鼠還沒動時，顯示靜止的光影漸層；滑鼠移動時，光會沿著軌跡流動，之後慢慢恢復平靜。
- 手機：背景是深色單色，不做光影，以影片為主體。影片一樣自動播放。
- 降級：裝置開啟「減少動態效果」（`prefers-reduced-motion`）或省流量模式時，影片只顯示封面圖。WebGL 無法執行時，桌機改用靜態漸層。
- News 輪播：自動抓取專欄最新 3 篇文章，點擊後進入文章內頁。
- 驗收：封面圖比影片先顯示，版面不會跳動；手機不會載入 WebGL 程式；WebGL 關閉時畫面依然完整。

**M-03 首頁區塊**
- 依照這個順序排列：Hero → 精選作品 → 先設計、再開工 → 資產屬於客戶 → 不只是網站（客製化功能＋創意小物）→ 專欄 → CTA → Footer。
- 首頁不放商城區塊。
- 「先設計、再開工」區塊或 CTA 旁邊，放一句公開起價：「形象網站 NT$XX 起，實際報價依需求」（金額見開放問題 #1）。
- 驗收：區塊順序與內容符合上方規定；「不只是網站」的卡片會連到網站案例頁的對應段落。

**M-04 網站案例頁**
- **只展示作品**（業主 2026-09-29 決定的方向）：WordPress 網站製作、客製化功能、行銷自動化、創意小物、企業應用、API 串接等類別的作品。
- 「先設計、再開工」「網站資產屬於客戶」這類說明服務與承諾的文字，暫定移到「關於我們」（見開放問題 #7）。
- 放一個專欄區塊（資訊欄＋列表）。
- 頁尾有導向諮詢的 CTA。
- 版面結構見開放問題 #6。

**M-05 專欄**
- WordPress 新增獨立的「網站架設專欄」分類，只有這個分類的文章會出現在本站。
- 列表頁與首頁、案例頁的專欄區塊都用同一種版面：資訊欄＋文章列表。資訊欄只放**分類篩選**和**諮詢 CTA 小卡**。
- 首頁和案例頁的區塊顯示最新幾篇文章，另外附上「看全部」連結，連到列表頁。
- 文章內頁的內容來自 WordPress，SEO 欄位使用 Yoast。
- 同事在 WordPress 發布或更新文章後，前台會自動更新，不需要工程師重新部署。

**M-06 商城頁與商品頁**
- 商品只有 Flatsome（NT$1,200）和 Astra Pro（NT$1,999）兩項。
- 商城頁用兩欄並排比較：適合誰、包含什麼、交付方式。
- 商品頁底部放一行小字「不想自己架？交給我們」，連到諮詢表單。

**M-07 購物車與結帳**
- **購物車、結帳、付款結果頁都由 WordPress／WooCommerce 原生頁面處理**（業主 2026-10-04 決定）。前台的其他頁面仍用 Next.js 製作；商品頁的「加入購物車」連到 WooCommerce 的購物車網址，綠界付款與電子發票沿用現行商城的綠界外掛。兩套系統要在同一個網域下運作。
- 這幾頁的樣式靠調整 WordPress 佈景主題的 CSS，做成跟前台一致的深色風格；綠界的刷卡頁是綠界的畫面，無法設計。
- 不需要登入，訪客填寫 Email 就可以結帳。
- 發票類型三選一：個人（手機條碼／自然人憑證條碼／會員載具）、捐贈、公司（統編＋抬頭）。
- 購物車裡有 Astra Pro 時，多一個必填欄位「要啟用的網站網址」。**結帳時不收集 WordPress 後台帳號密碼。**
- 付款只開放信用卡，按下付款後跳轉到綠界刷卡頁。
- 驗收：用綠界測試環境走完整個流程，WooCommerce 的訂單狀態會正確更新。付款結果以綠界伺服器傳來的通知為準，不以瀏覽器導回的網址為準。

**M-08 付款結果與訂單通知**
- 付款成功頁：顯示訂單摘要與交付說明。Flatsome 寫「12 小時內寄送金鑰」；Astra 寫「會在 X 小時內寄信協助啟用」（時數見開放問題 #4）。頁面下方附上「需要協助設計或架站可以找我們」。
- 付款失敗頁：說明付款沒有成功，並提供回到結帳頁重試的入口。
- 訂單確認信：內容跟付款成功頁一致，同樣附上導向諮詢的一句話。
- 付款成功後，由綠界自動開立電子發票並寄給客戶。

**M-09 聯繫我們與諮詢表單**
- 表單約 5 個欄位：姓名、聯絡方式、網站類型、預算區間、需求說明（選項內容見開放問題 #2）。
- 表單旁邊放 LINE 官方帳號按鈕。
- 送出後進入感謝頁。
- 表單資料存進 WordPress 後台，同時寄通知信到指定信箱。資料要有「來源」欄位，標記為網站架設站，以便跟行銷站的表單區分。
- 驗收：通知信寄送失敗時，WordPress 後台仍然保有這筆資料。表單要有防垃圾訊息機制。

**M-10 視覺風格**
- 深色底搭配發光漸層，跟 Landing page 的深色調連貫，跟行銷站的灰白調明顯區隔。
- Header 和 Footer 都跟行銷站不同。
- 驗收：由業主主觀判定是否有作品感，不另外訂定數字標準。

**M-11 響應式**
- 以 1920px 為設計基準，在 1440px、1280px、平板、手機（375px）都能正常瀏覽，而且不會出現橫向捲軸。

**M-12 GA4 關鍵事件**
- 追蹤四個事件：諮詢表單送出、LINE 點擊、加入購物車、完成購買。
- 這些數據不作為驗收標準，只用來事後檢討。

**M-13 SEO 技術基礎**
- **伺服器端輸出**：每一頁都用 Next.js 在伺服器端產生完整的 HTML（SSR 或 SSG＋ISR），搜尋引擎不必執行 JavaScript 就能讀到內容。
- **Meta 資料**：title、meta description、canonical、Open Graph、robots 都從 WordPress 的 Yoast 欄位讀取（透過 WPGraphQL），讓行銷同事可以自己修改。
- **標題結構**：每頁只有一個 `<h1>`。首頁 Hero 的主標要是 HTML 文字，不能只存在影片或圖片裡；影片和 WebGL 都不能延遲主標的顯示。
- **結構化資料（JSON-LD）**：全站加 Organization；內頁加 BreadcrumbList；專欄文章加 Article；商品頁加 Product＋Offer（含價格與幣別）。
- **Sitemap 與 robots**：由 Next.js 自動產生 `sitemap.xml`（包含首頁、案例、專欄列表與文章、商城、商品、聯繫我們），並提供 `robots.txt`。新文章發布後，sitemap 會跟著更新。
- **不需要收錄的頁面**：購物車、結帳、付款成功／失敗頁、感謝頁設為 `noindex`。專欄列表的分類篩選結果，要設定 canonical 或 `noindex`，避免產生大量重複網址。
- **圖片與影片**：圖片使用 Next.js 的圖片元件，並填寫有意義的 alt 文字；影片要有封面圖，影片旁邊要有文字說明它的內容。
- **擋掉 WordPress 前台**：WordPress 本身的前台頁面不能被 Google 收錄，避免跟 Next.js 前台的內容重複（原本是 S-03，這次升級為 Must）。
- **網址**：使用有意義的網址，例如 `/cases`、`/column/文章代稱`、`/shop/astra-pro`，實際規則見開放問題 #19。
- **手機版 Core Web Vitals**：LCP ≤ 2.5s、CLS ≤ 0.1、INP ≤ 200ms，以首頁、網站案例、專欄文章、商品頁為量測對象。桌機版不設門檻。
- 驗收：用 Google Rich Results Test 檢查結構化資料沒有錯誤；檢視網頁原始碼，可以直接看到內文和 meta；上線後在 Google Search Console 提交 sitemap，而且沒有收錄錯誤。

### Should Have

- **S-01** 案例截圖加上裝置模型或外框，避免淺色截圖在深色底上太刺眼。
- **S-02** 每個頁面都有 Open Graph 分享圖和描述；專欄文章使用文章的精選圖片。
- **S-03** 專欄文章內頁的最後附上 2～3 篇相關文章，並連到相關的案例，讓網站內部的連結互相串起來。
- **S-04** News 輪播在滑鼠停在上面時暫停，而且可以用鍵盤切換。

### Could Have

- **C-01** 專欄列表頁的分頁或「載入更多」按鈕（文章數量多了以後才需要）。
- **C-02** 自訂的 404 頁面，沿用深色視覺並導回首頁和網站案例頁。
- **C-03** 捲動時的區塊進場動畫（前提是不能跟 Hero 搶注意力）。

### Won't Have（這一版不做，詳見「非目標」）

- 會員系統、ATM 轉帳與超商代碼付款、多語言、首頁的商城區塊、方案價格表。

## 非目標（明確不做）

1. **不做會員系統**：不做註冊、登入、會員中心、歷史訂單查詢。
2. **不開放 ATM 轉帳和超商代碼**：只開放信用卡，所以不設計「待付款」畫面，也不處理逾期訂單。
3. **不做多語言**：只做繁體中文，沒有語言切換功能，也不設定 hreflang。
4. **不販售相鼎學院的課程**：現行商城上的 8 堂課程不搬到本站。
5. **不擴充商品**：只有 Flatsome 和 Astra Pro 兩項，不做商品分類、搜尋或篩選。
6. **首頁不放商城區塊**：商城的入口只有側邊欄。
7. **不公開方案價格表**：只公開一句起價。
8. **不做離開前彈窗**：也不做任何強迫留下名單的機制。
9. **不在首頁放行銷自動化、企業應用、API 串接**：這三類只放在網站案例頁。
10. **Hero 影片不做聲音**，也不提供開啟聲音的按鈕。
11. **手機不做光影和觸控互動**：手機版是深色單色背景。
12. **專欄資訊欄不放熱門文章和作者介紹。**
13. **不跟行銷站的商學院共用文章**：每篇文章只屬於一個站。
14. **結帳時不收集客戶的 WordPress 後台帳號密碼。**
15. **不用數字 KPI 驗收**：GA4 數據只用來事後檢討。唯一的數字門檻是手機版的 Core Web Vitals（M-13）。
16. **桌機版不設效能門檻**：WebGL 光影以作品感優先。

## 開放問題（尚未拍板，不預設答案）

**內容與營運**
1. 形象網站**架站服務**的起價是多少？這是首頁「形象網站 NT$XX 起」要放的金額，跟商城商品的售價不同。
2. 諮詢表單中「網站類型」和「預算區間」的選項內容？
3. 表單通知信要寄到哪個信箱？由誰負責回覆？
4. Astra 付款後，要在幾小時內寄信協助啟用？需要後台權限時，用什麼方式交接？
5. LINE 官方帳號的連結。

**頁面範圍**
6. 網站案例頁的作品要怎麼分類、排序？首頁「精選作品」要放哪幾個？案例資料要用 WordPress 自訂文章類型管理，讓同事可以自己新增嗎？
7. 「關於我們」的內容。**暫定方向**：沿用現行案例頁的說明文字（例如先設計再開工、資產屬於客戶），讓案例頁只放作品。業主還在考慮，尚未定案。
8. 「聯繫我們」是獨立頁面，還是連到首頁 CTA 區塊的錨點？
9. 專欄上線時至少要有幾篇文章？（少於 3 篇時，News 輪播和專欄列表會顯得空）專欄分類要怎麼命名？
10. Flatsome 說明中「曾用於專案測試、不含 6 個月官方支援」這些字樣要保留嗎？

**法規**
11. 退款政策、服務條款、隱私權政策由誰提供？販售數位商品通常需要這些頁面，現行商城的版本可以沿用嗎？
12. 使用 GA4 需要顯示 Cookie 同意橫幅嗎？

**SEO**
13. 專欄和各個頁面要鎖定哪些主要關鍵字？由誰負責研究？例如「形象網站設計」「WordPress 架站」。
14. 網址規則：專欄文章的網址要用英文代稱還是中文？商品頁的網址要用什麼路徑？

**素材與架構**
15. Hero 影片和封面圖什麼時候交付？Jitter 需要輸出桌機和手機兩種解析度。
16. 網站架設站要跟行銷站（目前是 `martech-page/` 獨立的 Next.js app）合併成同一個專案，還是分開部署？這要看網域規劃再決定。

## 已確認／延後處理

- **商品售價（2026-09-29 確認）**：WordPress 佈景主題（Flatsome）NT$1,200，Astra Pro NT$1,999。商品頁和商城頁以刪除線顯示原價（Flatsome NT$1,950、Astra NT$6,990）。
- **綠界**：沿用現行商城一直在使用的綠界帳號，不需要重新申請特店。如果這個帳號還沒開通電子發票服務，要另外開通。
- **舊網址轉址（延後）**：業主決定等三個站都設計完成後再處理，不在這一版的範圍內。屆時要整理舊網址（`/cases/`、`/mall/`、商品頁、文章）和新網址的對應表，並設定 301 轉址。
