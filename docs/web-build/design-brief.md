# Design Brief — Blazelink 網站架設站

> 狀態：兩輪訪談都已完成（2026-09-29），所有決定都已寫進正文。還沒決定的營運事項，改列在 `prd.md` 的「開放問題」。

## 專案背景

Blazelink 的新站台分成三層，全部用 Next.js＋headless WordPress 建置，放在同一個網域：

```
Landing page（流量入口）
├── CTA → 行銷首頁：關於我們／跨國SEO行銷／商學院／聯繫我們
└── CTA → 網站架設首頁：關於我們／網站案例／商城／聯繫我們   ← 本案
```

- **本案範圍**：首頁、網站案例、商城、結帳流程、聯繫我們，以及專欄（見第 7 節）。全站只做繁體中文。主要設計尺寸是 desktop 1920px，需要做響應式。網站案例的內容來源是現有的 <https://blazelink.co/cases/>，商城的內容來源是 <https://blazelink.co/mall/>。
- **商城**：串接綠界做真實金流，只賣 WordPress 佈景主題和 Astra。販售量不大，主要目的是讓想做形象網站的人來諮詢。
- **與行銷站的關係**：兩站的 Header 和 Footer 設計不同。行銷站負責「B2B 要名單、要轉換」的受眾，本站不跟它搶同一群人。

---

## 1. 專案定位

**以諮詢為主，商城是配角。**

首頁的主敘事是作品、流程、承諾，最後全部收斂到諮詢。商城會出現在 nav，首頁最多放一個小入口，服務想自己動手架站的訪客。理由是一個佈景主題的營收遠低於一個架站案，所以商城不應該搶走首頁的注意力。

## 2. 成功判準

**以作品感為主。** 業主和潛在客戶看到網站，就會覺得「這家做的網站很厲害」，網站本身就是作品集。

- **效能門檻只套用在手機版**（因應 SEO 追加決定）：手機版要達到 Google Core Web Vitals 的「良好」標準，也就是 LCP ≤ 2.5s、CLS ≤ 0.1、INP ≤ 200ms。Google 以手機版評分，而手機版本來就不執行 WebGL。桌機版以作品感優先，不設數字門檻。
- **驗收方式：由業主主觀判定。** 業主認為有作品感就算通過，不另外訂定參考網站或規格清單。
- **仍然設定 GA4 關鍵事件追蹤**：諮詢表單送出、LINE 點擊、加入購物車、完成購買。這些數據不作為驗收標準，只用來事後檢討。

## 3. 受眾設定

**要做形象網站的品牌主。** 例如中小企業老闆、品牌主理人、專業服務業（會計師、顧問、藝文機構）。

- 他們不懂技術，在意的是網站能不能讓自己看起來很專業。
- 他們的顧慮依序是：做出來好不好看 → 會不會跟想像的不一樣 → 會不會被綁住。
- 文案重點放在質感、流程透明、上線後可以自己更新，技術名詞盡量少用。現有案例（GOGOHSU、成智會計師事務所、曜畫廊、美成移民、相鼎學院）剛好都是這類客戶。

## 4. 視覺方向

**深色底加上發光漸層。**

- 近黑色的底，Hero 底部的漸層光影會發光，9:16 影片看起來像是被打了光的展品。
- 跟 Landing page 的深色調連貫，訪客從入口點進來，不會覺得跳到另一家公司。
- 跟行銷站的「灰白顧問白」明顯區隔，Header 和 Footer 也各自獨立。
- **要注意**：案例截圖大多是淺色網站，放在深色底上要加裝置模型或外框，才不會刺眼。

## 5. 內容範圍

素材來源是案例頁的 8 大區塊。依照品牌主的三個顧慮，選其中 3 項放進主敘事：

| # | 案例頁區塊 | 處理方式 |
|---|---|---|
| ① | WordPress 網站製作 | **主敘事**：精選作品（回答「好不好看」） |
| ② | 先設計、再開工 | **主敘事**：設計藍圖流程（回答「會不會跟想像的不一樣」） |
| ③ | 網站資產完全屬於客戶 | **主敘事**：網域、主機、內容都歸客戶所有（回答「會不會被綁住」） |
| ④ | 額外客製化功能 | 簡短帶過：和⑥合併成一個「不只是網站」小區塊，用卡片加連結呈現 |
| ⑥ | 創意小物（互動遊戲） | 簡短帶過：同上，用來展現創意和記憶點 |
| ⑤ | 行銷自動化系統 | 只放在案例頁（偏 B2B，跟行銷站重疊） |
| ⑦ | 企業應用案例 | 只放在案例頁 |
| ⑧ | API 串接 | 只放在案例頁 |

**首頁區塊順序**（順著品牌主的顧慮逐一解除，最後才放加分內容）：

1. Hero
2. ① 精選作品
3. ② 先設計、再開工（這個區塊或 CTA 旁邊附上公開起價，見第 8 節）
4. ③ 資產屬於客戶
5. 不只是網站（④⑥）
6. 專欄（承接還在猶豫的訪客，見第 7 節）
7. CTA：表單＋LINE
8. Footer

**首頁不放商城區塊。** 側邊欄導覽和購物車全站都看得到，想買主題的人找得到入口，首頁保留完整的諮詢敘事。

## 6. Hero 技術路線

**版面構成（業主既有構想）**：logo 在左上角，Header 是**直立在右側的側邊欄**，中間是 9:16 影片（不滿版），底部是漸層光影動畫，右下是 News 輪播。

**News 輪播**：自動抓取專欄最新 3 篇文章，點擊後進入文章內頁。只要專欄持續更新，內容就不會過期，也不需要另外維護。

**側邊欄**：全站固定在右側的窄欄（約 80～120px），導覽文字直排，捲動時一直留在畫面上。導覽由上到下依序是：網站案例／關於我們／專欄／商城／聯繫我們。作品最有說服力，所以放在第一項；商城是配角，所以排在後面。購物車和諮詢按鈕放在欄內底部。手機版收成右上角的漢堡按鈕，按下後展開全螢幕選單。

**技術決定：影片放在自己的網站上，光影用 WebGL 並由滑鼠軌跡觸發。**

- **影片**：業主用 Jitter 製作，內容是案例網站畫面，長度約 13 秒，靜音自動循環播放，不需要聲音按鈕。提供 WebM 和 MP4 兩種格式，桌機版約 3MB 以內。影片還沒載入前先顯示封面圖，封面圖就是 LCP 元素，避免拖慢載入。
- **桌機光影**：滑鼠還沒動時，顯示靜止的光影漸層（有光但不動）；滑鼠移動時，會沿著軌跡讓光流動，之後慢慢恢復平靜。用 WebGL shader 實作。畫面上唯一一直在動的東西是影片。
- **手機版**：背景是深色單色，不做光影，以影片為主體。影片同樣自動靜音循環播放，但載入壓縮過的版本（約 1～1.5MB）。
- **降級方案**：裝置開啟「減少動態效果」（`prefers-reduced-motion`）或省流量模式時，影片只顯示封面圖。WebGL 無法執行時，桌機改用靜態漸層。

## 7. 邊界情況處理

**主要情境：訪客對作品有興趣，但還沒準備好諮詢**（最常見的原因是不知道預算大概多少，所以不敢填表）。

**處理方式：做一個專欄（類似部落格文章）來承接這群訪客。** 讓他們先透過文章認識 Blazelink、建立信任，之後再回來諮詢。

- 專欄文章會出現在**首頁**和**網站案例頁**，版面是「資訊欄搭配文章列表」，最新幾篇加上「看全部」連結。
- **資訊欄只放兩樣東西**：分類篩選，以及諮詢 CTA 小卡（一句話加上按鈕，連到諮詢表單）。不放熱門文章或作者介紹，避免看起來像傳統部落格的側欄。
- **頁面**：專欄有自己的列表頁（同樣是資訊欄＋列表）和文章內頁，並加入側邊欄導覽（排在第 3 項）。
- **內容來源**：在 WordPress 新增獨立的「網站架設專欄」分類，主題限定品牌形象、網站設計、WordPress 使用。行銷站的「商學院」繼續寫行銷內容，每篇文章只屬於一個站，避免 Google 判定為重複內容。
- 專欄跟相鼎學院的課程無關，相鼎學院的課程不放在本站。

**其他情境：**

- **不知道預算所以不敢問**：公開起價，見第 8 節。
- **在商城買了主題之後，發現自己做不出來**：從商品頁、付款成功頁和確認信導向諮詢，見第 9 節。
- **只看了 Hero 就離開**：沒有另外設計處理方式。Hero 的 News 輪播（專欄最新 3 篇）和側邊欄導覽，提供了不用往下捲就能前往其他內容的入口。

## 8. CTA 終點

**以站內表單為主，LINE 為次要管道。**

- **主要**：站內諮詢表單，約 5 個欄位（姓名、聯絡方式、網站類型、預算區間、需求說明），送出後進入感謝頁。「網站類型」和「預算區間」是用來預先篩選客戶。
- **次要**：LINE 官方帳號按鈕，放在表單旁邊，給不想填表的人使用。
- **資料去向**：表單資料存進 WordPress 後台，同時寄通知信到指定信箱。行銷站的諮詢表單也送到同一個地方，用「來源」欄位區分是哪一站送來的。
- **公開起價**：只寫一句「形象網站 NT$XX 起，實際報價依需求」，放在「先設計、再開工」區塊或 CTA 旁邊。不公開方案表。

## 9. 商城與結帳

- **商品**：只有 Flatsome（NT$1,200，付款後 12 小時內用 Email 寄送金鑰）和 Astra Pro（NT$1,999，公司授權代綁）兩項。因為商品少，商城頁用兩欄並排比較（適合誰、包含什麼、交付方式），不做商品列表或分類。
- **訂單管理**：訂單存在 WordPress 的 WooCommerce，透過綠界外掛處理付款，同事可以在 WP 後台查看訂單。
- **購物車與結帳交給 WordPress（2026-10-04 決定）**：商城頁、商品頁由 Next.js 製作，「加入購物車」之後的購物車、結帳、付款結果頁都是 WooCommerce 原生頁面，用佈景主題 CSS 調成一致的深色風格。
- **不做會員系統**：訪客填 Email 就能結帳，訂單確認信寄到信箱。
- **付款方式**：只開放信用卡。不設計「待付款」畫面，也不用處理逾期未付款的訂單。
- **發票**：串接綠界電子發票，付款成功後自動開立。結帳時可以選擇發票類型：個人（手機條碼、自然人憑證條碼、會員載具）、捐贈、公司（統編＋抬頭）。
- **Astra 交付**：購買 Astra 時，結帳表單多一個必填欄位「要啟用的網站網址」。付款成功頁和確認信會說明我們將在幾小時內寄信協助啟用。**結帳時不收集 WP 後台帳號密碼**，需要後台權限時，另外用安全的方式交接。
- **導向諮詢**：商品頁底部放一行小字「不想自己架？交給我們」，連到諮詢表單；付款成功頁和訂單確認信也附上「需要協助設計或架站可以找我們」。購買前不強力推銷。
- **結帳流程要設計的畫面**：購物車 → 結帳表單（含發票類型切換，購買 Astra 時多一個網址欄位）→ 跳轉到綠界刷卡 → 付款成功頁或付款失敗頁。

## 10. SEO

- **架構就是為了 SEO**：採用 headless 架構，就是為了讓 Next.js 在伺服器端輸出完整的 HTML，搜尋引擎可以直接讀到內容。
- **內容主力是專欄**：專欄有獨立的 WordPress 分類和自己的文章內頁，是這個站主要的關鍵字來源。跟行銷站的商學院分開寫，每篇文章只屬於一個站，避免 Google 判定為重複內容。
- **Hero 要兼顧 SEO**：影片和光影是視覺主角，但主標一定要是 HTML 文字，不能只出現在影片裡。
- **不需要收錄的頁面**：購物車、結帳、付款結果頁、感謝頁都設為不收錄。
- 手機版要達到 Core Web Vitals 門檻（見第 2 節）。
- 技術細節見 PRD 的 M-13。關鍵字和網址規則列在 PRD 的開放問題；舊網址轉址等三個站都設計完成後再處理。
